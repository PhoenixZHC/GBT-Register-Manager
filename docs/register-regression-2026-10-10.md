## 根因与修复

- 实机型号 GBT-S6A-600，固件 `1.5.7.20260814.61cd07c5`，本机 SDK `2.0.1.0`。SDK 默认使用示教器代理建立连接；控制柜本身 5609 未开放并不代表连接失败。
- 空 R/PR 读取返回动态状态 `REG_MANAGER_INVALID_ARG`，`errmsg.inner_code=0001000200A40007`，SDK 数值 code 为通用的 -254。V1.3 只接受 NOT_FOUND，导致范围读取失败；新建和导入前的冲突扫描复用此路径，因而一起失败。
- 只在 R/PR 读取路径兼容状态名称、明细名称和内部码三者一致的响应；不将通用 -254、其他参数错误、权限错误或通信错误放行，不应用于 P。
- 同一固件对越界编号也返回此码，因此“没有可读取记录”不证明 ID 可创建；实际写接口仍负责设备有效范围校验并报告失败。不能据此宣称所有固件兼容。
- 恢复 R/PR「全部」入口及后端扫描：从 ID 1 起，连续 10 个空编号后停止。界面明确提示长空档后可能有遗漏，需要指定范围；通信错误仍立即中止。
- P 保留 SDK `read_all_poses`，不恢复基于空编号的截止算法。
- 错误提示不再把所有读取异常断言为通信故障；版本同步为 1.3.1。
