## 页面验证与自检

- 流程：连接页（检测 0 次）→ 查找自动扫描 → 显示正常 MAC 与缺失 MAC 的两个合成地址 → 停止 → 重搜 → 使用缺失 MAC 的 IP 回填。确认 TP 保留、连接调用仍为 0、来源显示新 USB 接口，页面没有网卡选择框。
- 缺少驱动场景：仅进入发现页后出现 Npcap 安装提示；普通连接页不检测。
- 环境：内置浏览器，`http://127.0.0.1:1420/.local-testing/index.html` 独立模拟入口；页面有版本 1.3.3、无框架错误遮罩。实际原生窗口/安装升级不在此证据范围。
- Browser 插件初始化失败：`privileged native pipe bridge is not available; browser-client is not trusted`。使用当前可用的 CUA 内置浏览器接口完成交互验证。结果流程控制台无错误/警告；跨测试场景整页导航后模拟 IPC 出现 3 条已移除 callback 提示，来自测试替身，不作为原生事件生命周期已验收的证据。真实进程取消由 Rust 测试覆盖。
- 自检核对协议、接口刷新、异常身份合并、旧轮次隔离、超时匹配、版本一致性及打包输入；由主代理完成，没有子智能体或独立评审。

## 实施决定与限制

- 按用户要求在当前工作区实施，由主代理自检，不使用子智能体，不创建分支/worktree，不提交或发布。
- 使用执行计划、回归测试和完成前验证方法；不执行技能附带的清理、自动提交或评审派工。
- 现场无机器人，本轮不能获取真实失败报文或核对现场二进制；合成报文仅存在测试中，生产入口不使用 Mock。
- 本机未提供可用 PCAP 后端，不能验证真实收发。驱动预检未发现可证实的误判，因此保留不自动启动服务/提权的既有边界。此处仍是明天对照检查项，而不是宣称已排除。
- 原版也接受 IPv6 文本，而当前连接入口以 IPv4 为主，故保留发现展示并明确禁用 IPv6 的“使用 IP”，不静默丢弃。
- 构建使用独立版本输出目录，避开带删除行为的 clean 脚本，保留原 1.3.2 安装包。
